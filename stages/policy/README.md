# stages/policy

Policy training: FlashSAC of FlashCHORD. We train one policy per tier and episode. The output is `policy_<step>.safetensors`. Training and evaluation both run in the
`flash_chord:latest` container. The artifacts go to `runs/` and are not in git. For the method and the variants (`r3a`, `r3o`, `c10` and others), see
[Section 4.4 of the engineering handbook](../../docs/engineering/v2d-track2-engineering-handbook.zh.md) (in Chinese). For the contract, see [`docs/contracts/policy.md`](../../docs/contracts/policy.md).

Entry points:

- `fc_run.sh`: the host entry point for one run. It does resume from checkpoints, W&B, run records and automatic retries.
- `day2_train_chain.sh`: the training chain. It first runs a smoke test for each run, then the full training for each run. At the start, the chain records the source commit. If the commit changes, the chain stops.
- `arm_after.sh`, `relay_when_armed.sh`: connect several chain segments in series on the same host.
- `precheck_expect.sh`, `assert_cfg.py`, `fc_config_check.sh`: configuration checks before training starts.
- [`queues/`](queues/): the run list and the expected configuration of each training chain. This directory has its own index.
