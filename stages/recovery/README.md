# stages/recovery

Tier 2 denoising, and the takeover, runs and checks of the Tier 3 reconstruction. Tier 1 does not go through this stage. For the method, see
[Sections 4.2 and 4.3 of the engineering handbook](../../docs/engineering/v2d-track2-engineering-handbook.zh.md) (in Chinese). For the contract, see [`docs/contracts/recovery.md`](../../docs/contracts/recovery.md).

**The Tier 2 part of this stage must not read any Tier 1 data.** This includes use as a supervision signal, a calibration reference or a validation set (ADR-00002). The submission pipeline and the
Tier 2 evaluation scripts call `forbid_tier1()` of `libs/v2d_infra/tier_guard.py` at their entry point.

## Tier 2 submission pipeline (v5.4)

| File | Purpose |
|---|---|
| `export_tier2.py` | Entry point: `python3 stages/recovery/export_tier2.py v5.4` (you must give the version, there is no default). It writes `runs/recovery/tier2_v54/episode_XXXXXX.npz` |
| `v51.py` | Denoising: stationary criterion, integration over stationary segments, 3-DoF anchoring to the support surface, Brownian bridge |
| `t2core.py` | Pure functions that read no data (integration, correction, bridge) |
| `nopen.py` | No-ground-penetration constraint |
| `cleanroom_params.py` | Derives the v5.4 parameters from Tier 2 only. It writes `runs/recovery/cleanroom_params.json` |

`t2eval.py` is the evaluation that uses only Tier 2 (plan `agent-doc/plan-tier2-denoise-2026-10-04.md`). `denoise_v1.py`–`denoise_v4.py`,
`overfit_audit.py`, `fusion_ceiling.py` and others are development scripts from September. Most of them score against Tier 1. Their conclusions are background only, and the submission pipeline does not import them.

## Tier 3

From 10/21, we took over the reconstruction pipeline of a teammate on ml40 (`t3r_*`, `t3_*`, `t3fx_*`, `kfix/`). `t3r_run.sh` mounts the original directory read-only at the system level, then runs.
The reconstruction code (`stages/recovery/tier3/`) is not on this branch. It is on `track2/tier3-recon`. See the branch table in the root README.
