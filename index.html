Abstract

Track 2 of the NVIDIA Video-to-Data Challenge asks how much reconstruction error a robot policy can tolerate. Each entry provides one simulated humanoid policy per human-object interaction episode, built from clean multi-view trajectories (Tier 1), corrupted trajectories (Tier 2) or a single exocentric video (Tier 3). We train one FlashCHORD policy per episode and tier with an added object-orientation reward. Rules fixed in advance keep, per episode, the policy that tracks its own tier's reference best in 4096 simulated worlds. On the public leaderboard, the counted files reach an SP-SR of 0.867, 0.733 and 0.467 on Tiers 1, 2 and 3. On Tier 3, SP-SR rose from 0.267 to 0.467 over eleven days.

Why one policy both succeeds and fails, and how the worlds were picked

All worlds start from the same state and differ only through GPU non-determinism, which grows into different outcomes. From one 256-world rollout we picked worlds by fixed rules, without viewing the video. Success: the world closest to the median position error of successful worlds. Fall: the world with the median gap between object loss and the pelvis crossing its threshold. Near miss: the failed world without a fall closest to the median position error.

An object-orientation reward

The official recipe rewards only object position, so a policy can keep the object close to the reference while turning it the wrong way. We add a 13th reward term on the geodesic angle θ between the simulated and reference object orientations:

rori = w · exp(−θ2 / σ2),   w = 1.0,   σ = 0.4 rad

Reconstruction

Grounding DINO and SAM 2 segment the person and the object. CARI4D (MoGe-2 depth, FoundationPose tracking, contact refinement) and the SOMA body model reconstruct both. Later versions add calibrated intrinsics, ground and depth correction, a dynamics pass and temporally consistent object poses.

Frame-0 alignment

Tier 3 has no released camera calibration. As the organizers permit, one rigid transform per episode, chosen by a fixed yaw rule, maps our frame 0 to the Tier 1 frame-0 pose. It changes only the frame references, so no policy is retrained.

Limitations

  • Some episodes fail on every tier: the object leaves the reference soon after first contact, mostly by turning. Known Tier 3 causes are reference objects that turn before contact and objects that start on high surfaces.
  • The leaderboard scores one exported rollout per episode. Because of GPU non-determinism, a policy with a high 4096-world success rate can still fail there.
  • Tier 2 and Tier 3 selection uses scores vs. our own reference, which overstate leaderboard gains, most of all on Tier 3.
  • Each policy serves one episode, and all results are in simulation.
